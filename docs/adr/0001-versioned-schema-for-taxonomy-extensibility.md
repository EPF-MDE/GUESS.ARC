# Versioned schema, not an open key-value store, for taxonomy extensibility

We need to add new tags or Interaction types to the taxonomy over time (e.g. once Gear 5 debuts, or when a second Interaction type is added) without invalidating everything already tagged. We considered a fully open/schemaless key-value tag store, where adding a tag is just inserting data with no schema change at all. We rejected it: it loses type safety, and every consumer (ML feature engineering in particular) would still need to track every historically-added key by hand, so the "no schema change" benefit is illusory. Instead, every taxonomy record carries a `Schema Version`; fields absent under an older version are simply read as null/unknown, and adding a field or Interaction type is a version bump, not a rewrite.
