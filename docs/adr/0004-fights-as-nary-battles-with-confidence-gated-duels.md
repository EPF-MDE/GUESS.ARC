# Fights as N-ary Battles with confidence-gated, optional Duels linked by a persistent Fight ID

The issue prompting this whole redesign (GitHub #2) is that a flat `fight_participants` list plus a single `fight_winner` cannot represent two separate simultaneous fights in one chapter (e.g. chapters 82-89, where Luffy/Zoro/Sanji/Usopp each fight a different named opponent as distinct duels, but all get merged into one list).

The obvious fix — a fixed two-sided `side_a`/`side_b` pairing — is also wrong: the Marineford arc (chapters 560-573) has chapters with 3+ distinct factions fighting simultaneously (Marines, Whitebeard Pirates, Straw Hats, Shichibukai), which a binary model can't represent without an artificial split. We chose an N-ary `Battle` (an arbitrary list of `Side`s) as the baseline shape instead, with an optional nested `Duel` (strictly two participants) asserted only when the source text explicitly supports that specific pairing — never inferred to fill in an unpaired Battle. This preserves the "never invent information absent from the source" constraint the original tagging approach already relied on.

Separately, fights commonly span many consecutive chapters without resolving (30+ runs of 3-7+ consecutive chapters with an unresolved fight were found in the existing corpus, e.g. chapters 418-426). Without a link between them, each chapter's segment of the same fight is a disconnected record — arguably a bigger instance of the "lost relational information" problem than the single-chapter pairing case the issue names as its example. Every Fight therefore carries a `Fight ID` stable across every chapter it spans, and a Side's or Duel's participants are either an individual Character or a Faction (not just a Character), since ~17% of fight chapters (91/550) include at least one faceless group combatant (e.g. "Morgan's soldiers") with no individual identity.
